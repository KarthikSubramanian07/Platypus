      How it works

      The call is the onboarding, not the product.

      01

      An agent asks

      Claude, Muse or any MCP client calls request_booking. We check Darwin first; if no agent covers the job, we route to the phone.

      02

      One honest call

      The first sentence says it is an AI. The voice agent books through hold_slot and create_booking mid-call, then asks: can I text you next time?

      03

      Texts forever after

      The yes is stored with the owner's exact words. Every later request is one text, answered with one letter.

      Rules the code enforces

      Confirmed means the owner said yes.

      • 01Only confirm() can set a booking to confirmed, and only with evidence: a quoted yes on the call, a Y by text, or a rule the owner approved.
      • 02Consent cannot be stored without the owner's sentence and the call it came from. The database refuses it.
      • 03Every state change is an append-only event with who did it, why, and how sure we are.
      • 04Only allowed numbers can ever ring. The check sits at the lowest layer, including the test fakes.
